## 1. 사용자가 최종적으로 요구한 업무 범위

### 1.1 졸업신고

기본 입력은 Excel 3개 탭이다.

- 실행설정
- 졸업신고명단
- 처리결과

필수 업무 흐름:

1. FIMS 로그인
2. 변동신고 메뉴 진입
3. Excel 명단을 기준으로 학생을 한 명씩 처리
4. 학번과 성명을 검색 조건에 입력
5. 성명 옆 유사 체크박스를 항상 체크
6. 조회
7. 조회 결과의 input[name="checkYn"] 중 title의 성명과 같은 행의 학번이 모두 일치하는 한 건만 체크
8. 보내기 실행
9. “선택된 유학생을 이동 하시겠습니까?” confirm 승인
10. 학생별 보내기 성공 또는 실패를 결과에 기록
11. 한 학생이 실패해도 다음 학생을 계속 처리
12. 보내기 완료 학생만 유학생신고 목록에서 다시 선택
13. 신고내용 일괄입력 팝업을 열어 사유발생일·신고구분·신고내용 입력
14. 저장 confirm과 완료 alert 처리
15. 최종 신고처리는 사용자가 직접 해도 괜찮다는 요구가 마지막에 명확히 나왔다

운영상 가장 중요한 해석:

- 화면을 처음 열었을 때 보이는 기존 목록을 Excel 명단으로 착각하면 안 된다.
- 기존 유학생신고 대기명단에 다른 학생이 있어도 오류로 중단하면 안 된다.
- 이번 Excel 대상만 정확히 체크해야 한다.
- 이미 대기명단에 이번 대상이 정확히 한 건 존재하면 중복 보내기를 하지 않고 “이미 보내기 완료 상태”로 인계할 수 있다.
- 동일 성명·학번이 대기명단에 중복되면 일괄 작업을 차단해야 한다.
- 최종 신고처리보다 “명단의 학생을 하나씩 조회 → 정확한 체크박스 선택 → 보내기 → 결과 기록”이 우선 목표다.

### 1.2 입국신고

기본 입력은 Excel 3개 탭이다.

- 실행설정
- 입국신고명단
- 처리결과

필수 업무 흐름:

1. 기존 FIMS 탭을 정리하고 새 전용 창에서 FIMS 접속
2. 페이지가 안정된 뒤 실행 화면에 입력한 ID·비밀번호로 로그인
3. 로그인 직후 “유학생현황/변동신고 반려처리 건수” 안내 alert가 실제로 뜬 경우에만 확인
4. 유학생정보관리 → 유학생기본정보 진입
5. Excel 명단의 성명과 생년월일 입력
6. 유사 체크박스를 항상 체크
7. 조회
8. 결과에 생성되는 학생 이름의 상세조회 링크 클릭
9. 상세화면에서 성명과 생년월일 재검증
10. 수정 클릭
11. 학번 입력
12. 입국일자/입국여부 콤보에서 “입국” 선택
13. 입학(복학)일자 입력
14. 저장 클릭
15. 저장 confirm 승인
16. 성공 alert 승인
17. 상세화면에 YYYY.MM.DD (입국)이 표시되는지 확인
18. 처리결과에 “입국신고 완료”와 확인된 입국일자를 기록
19. 입국일자가 보이지 않으면 “입국일자 미확인 / 별도 처리 필요”로 기록
20. 학생별 오류가 나도 다음 학생을 계속 처리

데이터 규칙:

- 입학(복학)일자 Excel 기본값은 20260901 형식이다.
- 생년월일, 학번, 날짜는 Excel에서 모두 텍스트로 취급한다.
- FIMS 입력 시 날짜는 2026.09.01 형식으로 변환한다.
- 성명은 반각 쉼표와 전각 쉼표를 공백으로 바꾸고 중복 공백을 정리한다.
- FIMS 여권명 표시 한도에 맞춰 정규화된 앞 38자를 검색·비교 기준으로 삼는다.
- 예: SAMPLE SURNAME, GIVEN MIDDLE → SAMPLE SURNAME GIVEN MIDDLE
- 예: SAMPLE LONGNAME TESTCASE OVERFLOW ALPHA → 정규화 후 앞 38자 기준

표입RPA(1).py의 중요한 점:

- Edge persistent context를 별도 프로필 폴더로 실행한다.
- 프로필 폴더는 _표입RPA_EdgeProfile_삭제금지 형태다.

이전 Python판과 현재 Chrome 확장판의 결정적 차이:

- Playwright persistent context는 실제로 별도 브라우저 프로필/컨텍스트를 만들 수 있다.
- Chrome 확장프로그램의 chrome.windows.create({type: "popup"})는 새 창일 뿐 같은 Chrome 프로필을 쓴다.
- 따라서 “완전히 격리된 전용 브라우저”가 요구되면 Chrome 확장프로그램만으로는 충족할 수 없다.

## 3. 입국신고 버전별 패치 내역

### 3.1 1.0.0 — Excel 기반 최초 구현

구현 내용:

- Google Sheets와 Apps Script를 제거하고 .xlsx 파일 직접 업로드 방식으로 구성
- 실행설정 / 입국신고명단 / 처리결과 3개 탭 사용
- FIMS 로그인, 유학생기본정보 메뉴 진입, 학생별 검색, 상세조회, 수정, 저장, 결과 검증 구현
- 로그인 정보는 메모리에만 두고 저장하지 않음
- 초기 manifest 권한에는 debugger가 들어가 있었음

### 3.2 1.0.1 — 로그인 경로 안정화 시도

문제:

- 로그인 페이지를 직접 열거나 잘못된 시점에 제출하면 FIMS가 빈 로그인 요청으로 판단해 “ID를 확인해주세요”를 띄웠다.
- Chrome debugger 권한 사용 시 브라우저 상단에 “디버깅을 시작함” 표시가 노출됐다.

변경:

- 직접 MembIsiLogin.isi를 GET으로 여는 방식에서 공식 진입점 흐름으로 이동하기 시작
- index.html과 bodyFrame/login.jsp 프레임 탐색을 도입
- debugger 의존 제거 방향으로 변경
- 로그인 후 메뉴 출현을 기준으로 성공 판정하도록 보강

### 3.3 1.0.2 — 실제 로그인 버튼과 선택적 안내창 처리

변경:

- 로그인 화면 안정화를 위해 약 2.5초 대기
- 수집된 실제 로그인 버튼을 1순위로 고정

    input[name="Button2"][onclick*="membLogin"]

- FIMS 자체 membLogin()이 숨김 필드와 POST를 처리하도록 실제 버튼 click 사용
- 로그인 뒤 유학생현황/변동신고 반려처리 건수 alert가 실제로 나타난 경우에만 자동 확인
- 해당 alert가 나타나지 않으면 메뉴 탐색으로 바로 진행
- “ID를 확인해주세요”는 정상 안내가 아니라 로그인 오류로 분리
- debugger 권한 제거

### 3.4 1.0.3 — 세션 초기화, 전용 창, 상세조회 링크 보강

변경:

- manifest에 cookies 권한 추가

## 5. 입국신고 현재 코드의 안전장치

- 검색 전 성명·생년월일·유사 체크가 화면에 유지되는지 검증
- 검색 결과 상세 링크가 여러 개면 이름 일치 후보 수를 계산
- 이름 일치가 한 건이면 해당 링크 선택
- 화면 이름이 말줄임표 처리돼도 링크가 딱 한 건이면 열되 상세화면에서 다시 검증
- 상세화면과 수정화면에서 성명·생년월일 재검증
- 학번 입력 후 유지 여부 검증
- #entrYN의 value N과 표시문자 입국을 모두 검증
- 입학일자 입력 후 유지 여부 검증
- 저장 후 입국일자와 (입국) 표시 검증
- 한 학생 오류 후 다음 학생 계속
- 비밀번호 비저장

남아 있는 위험:

- content.js의 setNativeValue가 focus/input/change/blur를 일괄 발생시키므로 FIMS의 구형 inline 이벤트와 충돌할 가능성
- 검색 프레임이 새 document로 교체되는 순간 documentToken 기반 대기가 사이트 타이밍과 안 맞을 가능성
- Chrome 자동완성은 readOnly 해제 직후에도 개입할 수 있어 1.0.4 실사이트 검증 필요
- Chrome extension popup은 별도 프로필이 아니므로 기존 프로필의 비밀번호 관리자·정책 영향을 완전히 차단하지 못함
- alert/confirm은 MAIN world bridge 주입 전에 뜨면 놓칠 수 있음

### 6.4 Google Sheets판에서 실제 발생한 문제

1. Apps Script 함수 목록이 myFunction만 표시

- 사용자가 Code.gs 전체를 붙여넣지 않았거나 기본 Code.gs의 myFunction이 남은 상태와 혼동
- 설치 절차가 너무 복잡했고 사용자가 어디서 어떤 함수를 실행해야 하는지 파악하기 어려웠음

2. 초기 설정 오류

~~~text
Exception: 이 작업은 유형이 적용된 열의 셀에서 사용할 수 없습니다.
setupTargetSheet_ @ Code.gs:174
setupFimsGraduationSystem @ Code.gs:80
~~~

- Google Sheets의 표/유형 열 메타데이터와 서식·고정 작업이 충돌한 것으로 보임
- 실제 사용자 시트에서 최종 해결 확인되지 않음

3. 확장프로그램 로드 실패

~~~text
매니페스트 파일이 없거나 읽을 수 없습니다.
매니페스트를 로드할 수 없습니다.
~~~

- 전체 패키지 최상위 폴더를 선택하고 manifest.json이 바로 들어 있는 확장프로그램 폴더를 선택하지 않아 발생
- 설치 구조가 사용자에게 불필요하게 복잡했음

4. Apps Script HTTP 404

- 웹앱 배포 URL이 아닌 라이브러리 URL 또는 잘못된 경로 사용
- /exec 배포 주소, 도메인형 주소, 권한 설정 사이 혼선

5. 응답 구조 오류

~~~text
Cannot read properties of undefined (reading 'spreadsheetId')
~~~

- 확장프로그램이 기대한 POST JSON 대신 안내용 GET 응답 또는 다른 래퍼 구조를 수신
- sheets-api.js에서 도메인형 URL을 표준 주소로 다시 시도하고 응답 구조를 검사하는 패치를 넣었지만 실사용에서 다시 실패

6. POST 대신 GET 안내 응답

~~~text
Apps Script가 POST 처리 대신 안내용 GET 응답을 반환했습니다.
~~~

- 네트워크·리디렉션·Google Workspace 도메인 배포 조합에 따라 확장프로그램 fetch가 웹앱 POST API에 안정적으로 도달하지 못함

결론:

- Sheets판은 자동화 핵심 로직보다 설치·인증·배포 장애가 더 커졌다.
- 사용자가 Excel 최종판으로 되돌릴 것을 요청했다.
- 후속 개발자는 별도 명시가 없는 한 Sheets판을 다시 살리지 말고 Excel판을 기준으로 작업해야 한다.

## 8. 졸업신고에서 실제 재현된 오류와 해석

### 8.1 초기 목록을 대기명단으로 오인

~~~text
기존 FIMS 대기명단이 현재 RUN_ID와 일치하지 않습니다:
필수 0건 / 실제 10건 / 다른 대기 대상 ...
~~~

원인:

- chgIntlStudFrame의 조회 결과와 notiListFrame의 신고 대기명단을 잘못 분류하거나
- 대기명단 전체가 현재 실행과 같아야 한다는 잘못된 선행조건 사용

올바른 동작:

- Excel 한 학생을 mainFrame에서 검색
- chgIntlStudFrame에서 그 학생의 체크박스만 선택
- 보내기
- notiListFrame에 그 학생이 들어왔는지만 확인
- unrelated rows는 그대로 두고 진행

### 8.2 조회는 됐지만 학생을 못 찾음

~~~text
[14:04:47] [WARN] [1/1] 조회 결과 확인 실패: 조회 완료 여부를 판정하지 못했습니다.
~~~

또 다른 실사례:

- SAMPLE BETA / 9900000003가 화면에 정확히 한 건 나타났는데 코드가 “학생 정보가 조회되지 않았습니다”로 판정

원인 후보:

- mainFrame의 검색 조건과 chgIntlStudFrame의 결과 갱신 타이밍 불일치
- 직전 documentToken 또는 결과 signature를 잘못 기다림
- 체크박스 자체가 아니라 초기 프레임을 읽음
- 이름·학번 셀 파싱 인덱스가 실제 표와 불일치

반드시 적용할 판정:

- chgIntlStudFrame에서 input[name="checkYn"][title]를 직접 수집
- title을 정규화해 Excel 성명과 비교
- checkbox.closest("tr") 전체 text에서 학번 숫자열 확인
- 정확히 한 건이면 click 후 checked===true 확인
- 조회 결과 총 1건이고 체크박스도 1개면 보조 안전 경로를 둘 수 있으나 같은 행 학번은 반드시 검증

### 8.3 보내기 confirm에서 멈춤

화면 문구:

    선택된 유학생을 이동 하시겠습니까?

상황:

- 학생 체크박스까지 선택
- 보내기 버튼도 눌림
- native confirm이 떠서 자동화 중단

필요 패치:

- 보내기 직전 MAIN world의 window.confirm을 임시로 true 반환하도록 설치
- topFrame/mainFrame/chgIntlStudFrame/notiListFrame 전부에 bridge 주입
- bridge 준비 확인 후에만 보내기 클릭
- confirm 로그에서 문구를 확인
- FIMS 목록 이동 또는 notiListFrame 행 출현을 성공 조건으로 삼기

가능하면 Playwright에서는 page.on("dialog", dialog.accept())를 보내기 전에 등록하는 방식이 더 신뢰성 높다.

### 8.4 대기명단 추가 학생 때문에 중단

~~~text
[16:47:31] [ERROR] 대기명단 불일치: 예상 1건 / 실제 2건 / 추가: SAMPLE STUDENT ALPHA/9900000004
~~~

- 이번 대상이 모두 정확히 한 건 존재하는지만 확인
- 기존 unrelated row 존재 자체는 허용

### 8.5 로그인 후 변동신고 진입 실패

- Sheets 2.0.6의 URL 직접 이동에서 회귀

## 10. 대화상자와 팝업 처리 설계

현재 두 Excel 프로젝트에 dialog-bridge.js가 있다.

기본 원리:

- MAIN world에서 window.alert와 window.confirm을 래핑
- confirm은 허용 모드일 때 true 반환
- alert/confirm 문구를 localStorage 등의 로그에 기록
- service worker가 프레임별로 bridge를 설치하고 기록을 읽음

문제:

- bridge 설치 전 사이트가 alert/confirm을 띄우면 놓침
- 새 popup 창은 별도의 tab/window 이벤트 추적이 필요
- 브라우저 팝업 차단으로 window.open 자체가 실패할 수 있음
- 네이티브 dialog가 이미 떠 있는 동안 extension script 메시지가 막힐 수 있음

후속 구현 권장:

1. 버튼 클릭 전에 관련 모든 프레임에 bridge 설치
2. bridge 준비 상태를 읽어 확인
3. popup을 여는 클릭은 사용자 제스처 연쇄 또는 MAIN world 직접 클릭으로 수행
4. chrome.windows.onCreated와 chrome.tabs.onCreated를 동시에 감시
5. URL이 ChgIntlStudPopupPageR.isi인 새 탭을 명시적으로 잡음
6. 팝업이 차단되면 자동 재클릭을 반복하지 말고 “팝업 허용 후 재시도”로 정확히 중단
7. 저장 버튼 클릭 전 popup frame에 confirm/alert bridge 설치
8. 저장 confirm → 완료 alert 순으로 로그를 검증

실운영 안정성이 최우선이면 Playwright 전환을 권장한다.

- 새 persistent context를 별도 사용자 데이터 디렉터리로 실행 가능
- page.on("dialog")로 native alert/confirm 안정 처리
- context.expect_page 또는 page.expect_popup으로 팝업 확보
- 브라우저 자동완성 영향이 적음
- 프레임 API가 Chrome extension 메시지보다 명확함

## 15. 권장 기술 방향

### 선택 1: 기존 Chrome 확장프로그램 유지

장점:

- 현재 Excel UI와 결과 다운로드 코드 재사용
- 설치 후 사용이 간단
- 소스가 이미 상당 부분 구현됨

단점:

- 진짜 독립 프로필 생성 불가
- 비밀번호 관리자/자동완성 영향을 완전히 차단하기 어려움
- native dialog와 popup 처리 경쟁조건
- frameset과 새 창 추적이 복잡

### 선택 2: Python + Playwright 실행파일로 통합

장점:

- 별도 persistent browser profile 가능
- dialog와 popup을 공식 API로 처리
- 프레임 대기와 값 입력 검증이 더 직접적
- 기존 표입RPA Python 로그인 코드 재사용 가능

단점:

- 배포 파일과 브라우저 런타임 관리 필요
- Chrome 확장프로그램보다 초기 설치가 다소 무거움

## 17. 최종 인계 결론

- 입국신고의 최신 작업점은 fims_arrival_rpa 1.0.4 소스다.
- 1.0.4는 로그인 자동완성 경쟁조건과 쉼표 성명 문제를 패치했으나 실사이트 검증 전이다.
- 입국신고 최신 배포 ZIP 1.0.3에는 재현 오류가 있으므로 그대로 최종판으로 쓰면 안 된다.
- 졸업신고는 fims_graduation_rpa 3.0.1 Excel판이 현재 기준이다.
- 졸업신고 Google Sheets 2.0.7은 Apps Script 설치·응답 문제 때문에 운영 기준에서 제외한다.
- 졸업신고의 우선 범위는 학생별 조회 → 정확 체크 → 보내기 → 결과 기록이다.
