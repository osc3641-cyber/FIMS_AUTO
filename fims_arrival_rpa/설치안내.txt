FIMS 입국신고 자동화 · Excel판 설치 및 사용 안내
=====================================================

버전: 1.3.1 (2026-09-14 정확성 우선 타이밍 — 입국일자 오판 수정)

[A. 압축 풀기]

1. `FIMS_입국신고_자동화_v1.3.1.zip`을 다운로드합니다.
2. ZIP 파일을 마우스 오른쪽 버튼으로 클릭하고 `압축 풀기` 또는 `모두 압축 풀기`를 누릅니다.
3. 압축이 완전히 풀린 폴더를 사용해야 합니다. ZIP 내부를 바로 열어 설치하면 안 됩니다.
4. 1.0.5부터는 폴더 구조가 한 단계 줄었습니다.
   압축을 푼 폴더를 열면 `manifest.json`이 **바로 보입니다.**
   (예전처럼 안쪽 폴더로 한 번 더 들어갈 필요가 없습니다.)

[B. Chrome 확장프로그램 설치]

1. Chrome 주소창에 아래 주소를 입력합니다.
   chrome://extensions
2. 오른쪽 위 `개발자 모드`를 켭니다.
3. 왼쪽 위 `압축해제된 확장 프로그램을 로드합니다`를 누릅니다.
4. 압축을 푼 폴더를 선택합니다.
   그 폴더 안에 `manifest.json`이 직접 보이면 맞게 고른 것입니다.
5. 이 상태에서 `폴더 선택`을 누릅니다.
6. 확장프로그램 목록에 `FIMS 입국신고 자동화 (Excel)`이 나타나면 설치 완료입니다.
7. 확장프로그램 상세정보에서 버전이 `1.3.1`인지 확인합니다.

※ `매니페스트 파일이 없거나 읽을 수 없습니다`가 뜨는 경우
   - `manifest.json`이 들어 있는 폴더가 아니라 그 바깥 폴더를 선택한 것입니다.
   - 폴더를 열었을 때 `manifest.json`이 직접 보이는 위치를 선택하세요.

[C. Excel 명단 입력]

1. `입국신고_업무파일.xlsx`를 엽니다.
2. `실행설정` 탭으로 이동합니다.
3. 노란색 `입학(복학)일자` 입력칸을 확인합니다.
   - 기본값: 20260901
   - 셀 형식: 텍스트
   - 입력 형식: YYYYMMDD 숫자 8자리
4. `입국신고명단` 탭으로 이동합니다.
5. 5행부터 학생을 입력합니다.
   - 처리대상: Y 또는 빈칸 = 처리 / N = 제외
   - 성명: 여권 영문명
   - 생년월일: 텍스트 형식의 YYYYMMDD 8자리
   - 학번: 텍스트 형식으로 숫자만 정확히 입력
   - 비고: 담당자가 미리 남길 내용이 있을 때만 입력
   - 현지추천단체 / 현지추천단체구분 / 최종출신학교: 선택 입력 (아래 S절 참고)
6. 입력 후 Excel 파일을 저장합니다.

[D. 로그인·메뉴 진입만 먼저 시험]

1. Chrome 오른쪽 위 퍼즐 모양 아이콘을 누릅니다.
2. `FIMS 입국신고 자동화 (Excel)` 옆 고정핀을 눌러 고정합니다.
3. 확장프로그램 아이콘을 누른 뒤 `실행 화면 열기`를 누릅니다.
4. FIMS 사용자 ID와 비밀번호를 입력합니다.
5. `로그인·메뉴만 점검`을 누릅니다.
6. 프로그램이 기존 FIMS 탭과 팝업을 닫고 FIMS 세션 쿠키를 삭제한 뒤 확장프로그램 전용 팝업 창 하나를 엽니다.
7. 새 창은 FIMS 공식 진입점 `index.html`에서 시작하며, 로그인 폼이 있는 `bodyFrame/login.jsp`를 사용합니다.
8. 로그인 화면이 안정될 때까지 2.5초 기다립니다. 입력칸을 잠가 브라우저 자동완성을 차단하고 기존 값을 지운 뒤, 잠금을 푸는 순간 실행 화면의 ID·비밀번호를 다시 넣고 즉시 로그인 버튼을 클릭합니다.
9. 실제 로그인 버튼 `Button2(membLogin)`을 누릅니다.
10. 로그인 후 `유학생현황/변동신고 반려처리 건수` 안내창이 뜨면 자동으로 확인합니다.
11. 이 안내창은 매번 뜨지 않습니다. 안 뜨는 경우에는 기다리지 않고 바로 다음 메뉴로 진행합니다.
12. `ID를 확인해주세요`가 뜨면 정상 안내가 아니라 로그인 실패로 기록하고 멈춥니다.
13. `유학생정보관리 → 유학생기본정보` 조회 화면까지 열리면 정상입니다.
14. 이 점검에서는 학생 정보가 수정되지 않습니다.

[E. 실제 입국신고 실행]

1. 실행 화면에서 `입국신고 엑셀 파일 선택`을 눌러 저장한 `.xlsx` 파일을 선택합니다.
2. `파일 검사`를 누릅니다.
3. 화면에 아래 정보가 보이는지 확인합니다.
   - 처리대상 인원
   - 입학(복학)일자
4. FIMS 사용자 ID와 비밀번호를 입력합니다.
5. 처음에는 실제 대상 학생 1명만 Y로 두고 시험하는 것을 권장합니다.
6. `새 FIMS 창 → 입국신고 시작`을 누릅니다.
7. 자동 처리 순서는 다음과 같습니다.
   - 기존 FIMS 창 종료 및 FIMS 세션 쿠키 삭제
   - 확장프로그램 전용 FIMS 팝업 창에서 자동입력 값 제거 후 사용자 입력 ID·비밀번호로 로그인
   - 유학생정보관리 → 유학생기본정보
   - 성명 + 생년월일 입력
   - 유사 체크
   - 조회
   - 학생 이름의 `a[title="상세조회"]` 또는 `a[onclick*="fncGetDetail"]` 링크 클릭
   - 상세화면 성명·생년월일 재확인
   - 수정
   - 학번 입력
   - 입국일자 콤보에서 `입국` 선택
   - 입학(복학)일자 입력
   - 저장
   - 저장 확인창과 완료창 자동 확인
   - 저장 후 `날짜 (입국)` 표시 확인
8. 학생 한 명이 실패해도 결과를 남기고 다음 학생으로 넘어갑니다.
9. 실행 중에는 FIMS 작업 창을 직접 클릭하거나 입력하지 마세요.
10. 목록의 이름이 `SAMPLE SUR...`처럼 줄어 보이더라도 상세조회 링크가 1개이면 열고, 상세화면에서 성명·생년월일을 다시 확인한 뒤에만 수정합니다.
11. 상세화면의 입국일자 `#eYmd`는 읽기 전용 결과값이므로 입력하지 않습니다. 저장 후 `날짜 (입국)` 검증에만 사용합니다.

[F. 결과 확인 및 저장]

1. 실행 화면의 처리결과 표를 확인합니다.
2. 주요 결과 뜻은 다음과 같습니다.
   - `입국신고 완료`: 저장 후 실제 입국일자가 확인됨
     (상세화면의 `날짜 (입국)` 표시 또는 수정화면의 입국여부 `입국` + 입국일자 중
      어느 쪽으로 확인됐는지가 상세메시지에 기록됩니다)
   - `입국일자 미확인`: FIMS 저장 완료 알림까지 확인됐지만 입국일자가 안 보임
     → 관서 출입국 기록 미연결. 아래 별도처리 섹션에서 처리합니다.
   - `입국정보 저장 실패`: 저장 자체가 되지 않음. 입국신고가 안 된 상태입니다.
     → 별도처리 대상이 아닙니다. 화면에서 직접 확인하세요.
       FIMS가 경고창으로 거부한 경우 그 문구가 상세메시지에 그대로 남습니다.
   - `이름, 생년월일 불일치`: 조회 결과가 없거나 대상 이름과 일치하지 않음
   - `동일 학생 다중 조회`: 같은 이름의 상세조회 결과가 여러 건이라 자동 수정 중단
   - `상세정보 불일치`: 상세화면의 성명 또는 생년월일이 엑셀과 다름
   - `저장 결과 확인 실패`: 저장 후 상세화면이나 입력값을 확인하지 못함
3. `입국일자 미확인` 학생은 비고에 `상세화면에 입국일자가 표시되지 않아 별도 처리 필요`가 기록됩니다.
4. `처리결과 엑셀 저장`을 누릅니다.
5. 다운로드된 파일의 세 번째 `처리결과` 탭을 확인합니다.
6. 결과 파일에는 확인된 입국일자, 비고, 상세메시지, 처리일시가 함께 저장됩니다.

[G. 긴 이름 처리]

FIMS에 여권명이 앞 38자까지만 저장된 경우를 반영합니다.

- Excel: SAMPLE LONGNAME TESTCASE OVERFLOW ALPHA
- FIMS:  SAMPLE LONGNAME TESTCASE OVERFLOW ALPH

앞 38자가 같으면 이름은 일치로 보지만, 생년월일이 정확히 같아야 다음 단계로 진행합니다.

Excel 성명에 쉼표가 있어도 FIMS 검색 전 자동으로 공백으로 바꿉니다.

- Excel: SAMPLE SURNAME, GIVEN MIDDLE
- FIMS 검색: SAMPLE SURNAME GIVEN MIDDLE

[H. 로그인 패치 확인]

1. 버전 1.3.1은 Chrome `debugger` 권한을 사용하지 않습니다.
2. `확장프로그램이 이 브라우저를 디버깅 중`이라는 안내 막대가 뜨면 구버전이 실행 중인 것입니다.
3. 로그인 시작과 동시에 `ID를 확인해주세요`가 뜨는 경우도 구버전의 직접 접속 방식이 남아 있는 것입니다.
4. 이때는 `chrome://extensions`에서 기존 확장프로그램을 삭제하고, 압축을 새로 푼 1.0.5 폴더를 다시 로드합니다.
5. 정상 버전은 기존 FIMS 탭을 닫고 FIMS 쿠키를 삭제한 뒤 확장프로그램 전용 팝업 창에서 로그인 폼을 엽니다. 2.5초 기다리고 입력칸을 잠가 자동완성을 막은 다음, 잠금을 푸는 순간 사용자 입력 ID·비밀번호를 다시 넣고 실제 로그인 버튼을 클릭합니다.
6. 로그인 후 현황 안내창이 뜨면 자동 확인 로그를 남기며, 안내창이 없으면 바로 메뉴 진입을 계속합니다.

[I. 다시 실행할 때]

1. 구버전이 설치되어 있으면 기존 확장프로그램을 삭제합니다.
2. 새 ZIP을 별도 폴더에 다시 압축 해제합니다. 기존 폴더 위에 덮어쓰지 않습니다.
3. `chrome://extensions`에서 `manifest.json`이 바로 보이는 새 1.3.1 폴더를 로드합니다.
4. 이미 열려 있던 실행 화면을 닫고, 확장프로그램 아이콘에서 새 실행 화면을 엽니다.
5. 화면 상단 또는 팝업에서 `v1.3.1`을 확인합니다.
6. Excel 파일을 다시 선택한 뒤 `파일 검사`부터 진행합니다.
7. 이미 저장된 학생을 재실행할 때는 FIMS 값이 다시 저장될 수 있으므로, 완료 학생은 엑셀 처리대상을 N으로 바꿔 중복 수정을 방지합니다.

중요: FIMS 사용자 ID와 비밀번호를 Excel 파일이나 메모에 넣지 마세요.

[J. 1.0.5에서 고친 것]

1. 저장이 실제로 성공했는데 `저장 결과 확인 실패` 또는 `입국일자 미확인`으로
   기록되던 문제를 고쳤습니다.
   저장 직후 FIMS가 읽기전용 상세화면(IntlStudBaInfoDtlR.xec)으로 가는 경우와
   수정화면(IntlStudBaInfoDtlRU.xec)에 그대로 남는 경우가 둘 다 있는데,
   예전에는 앞쪽만 기다리다 45초 뒤 실패로 처리했습니다.
   이제는 어느 화면이든 입국일자를 확인해 완료로 기록합니다.

2. 이전 실행에서 뜬 안내창 문구가 브라우저에 남아 다음 실행의 로그인을
   `FIMS 로그인 실패`로 잘못 판정하던 문제를 고쳤습니다.
   실행할 때마다 모든 프레임의 안내창 기록을 지웁니다.
   (증상: 아이디·비밀번호가 맞는데 실행할 때마다 되기도 하고 안 되기도 함)

3. 로그인 버튼이 눌리지 않았을 때 60초를 기다린 뒤 엉뚱한 메시지를 띄우던 것을
   고쳐, 실패 사유를 즉시 표시합니다.

4. 테스트가 특정 개발환경에서만 돌던 문제를 고쳐 어디서든 검증 가능합니다.

주의: 1.0.5는 로컬 자동 테스트를 모두 통과했지만, 실제 FIMS에서는 아직
검증되지 않았습니다. 반드시 학생 1명으로 먼저 시험하세요.

[K. 진단 모드 — FIMS에 저장하지 않습니다]

실제 저장 없이 "어디서 막히는지"만 확인하고 싶을 때 씁니다.
검색과 상세조회까지만 하고 수정·저장 직전에 멈춥니다.

1. 엑셀에 학생을 1명만 남기고(나머지는 처리대상 N) 저장합니다.
2. 실행 화면에서 엑셀을 선택하고 `파일 검사`를 누릅니다.
3. FIMS 사용자 ID와 비밀번호를 입력합니다.
4. `진단 (조회만 · 저장 안 함)`을 누릅니다.
5. 로그인 → 조회 → 상세조회 → 수정화면 열기 → 입력 재현까지 진행하고 멈춥니다.
   저장 버튼은 아예 눌리지 않습니다. 저장하지 않으면 FIMS에 반영되지 않습니다.
   끝나면 열린 FIMS 창은 그냥 닫으시면 됩니다.
6. 끝나면 `진단 리포트 저장`을 눌러 JSON 파일을 받습니다.
7. 그 파일을 개발자에게 전달하면 됩니다.

리포트에 들어가지 않는 것:
- FIMS 사용자 ID와 비밀번호 (애초에 수집하지 않습니다)
- 학생 성명·생년월일·학번의 실제 값

리포트에 들어가는 것:
- 각 단계의 성공/실패와 사유
- 프레임 주소와 구조
- 자동화가 찾는 요소가 실제로 있었는지, 잠겨 있었는지, 몇 글자였는지
- 성명·생년월일은 글자 수와 쉼표 위치만 남긴 형태 (예: XXXXXXX, XXXXX)

[L. 1.3.1에서 고친 것]

1. 학번이 화면에 남지 않는 문제에 재시도와 원인 기록을 넣었습니다.
   예전에는 학번을 넣고 → 입국여부를 바꾸고 → 입학일자를 넣은 다음에야
   학번을 검사했습니다. 입국여부 변경이 FIMS 쪽 처리를 유발해 학번이
   되돌아가면, 실제로는 잘 넣었는데도 실패로 처리됐습니다.
   이제는 각 칸을 DOM에서 다시 찾아 확인하고, 값이 밀렸으면 이벤트 없이
   한 번 더 조용히 넣습니다.
   그래도 실패하면 원인을 메시지에 같이 남깁니다.
   예: 학번 입력값이 유지되지 않았습니다.
       [#scholNo(길이 0/10, maxlength=20, 비어있음) / 재시도 함 / 입국여부 N·입국]
   "FIMS원래값으로되돌아감"이 찍히면 FIMS가 되돌린 것이고,
   "비어있음"이면 애초에 들어가지 않은 것입니다. 원인이 서로 다릅니다.

2. 신원 확인을 엄격하게 바꿨습니다.
   예전에는 화면의 모든 숫자를 이어붙인 문자열에서 생년월일을 찾았습니다.
   서로 다른 칸의 숫자가 우연히 이어지면 남의 상세화면을 대상 학생으로
   오인할 수 있었습니다. 이제 온전한 날짜 표기만 인정합니다.

3. 진단 모드가 수정화면까지 확인합니다. 저장은 여전히 하지 않습니다.

[M. 입국일자 미확인 학생 별도처리 (1.3.1 신규)]

입국신고는 저장됐는데 입국일자가 안 뜨는 학생이 있습니다.
관서(출입국) 기록과 아직 연결되지 않은 경우입니다.
이런 학생은 `재학생정보 수정대상자 조회 및 수정` 화면에서 기록을 연결해야 합니다.
1.3.1부터 실행 화면에서 바로 처리할 수 있습니다.

[M-1. 이어서 처리하는 경우]

1. 입국신고를 끝내면 실행 화면 아래 `입국일자 미확인 별도처리` 섹션에
   해당 학생들이 자동으로 나타납니다.
2. FIMS 사용자 ID·비밀번호가 입력된 상태에서 `별도처리 실행`을 누릅니다.

[M-2. 나중에 다시 처리하는 경우]

1. 저장해둔 `처리결과` 엑셀 파일을 `입국신고 엑셀 파일 선택`으로 올립니다.
2. `파일 검사`를 누릅니다.
3. 지난 실행 결과를 그대로 불러오고, 입국일자 미확인 학생이
   별도처리 섹션에 나타납니다.
4. `별도처리 실행`을 누릅니다.

[M-3. 자동 처리 순서]

1. 재학생정보 수정대상자 조회 및 수정 메뉴로 이동
2. 안내창 자동 확인
   ("관서에 등록된 정보와 일치하지 않거나, 체류만료일이 지난 유학생을…")
3. 성명·생년월일·학번 입력 후 조회
4. 결과에서 대상 학생 행을 찾음
5. `수정(새창열림)` 클릭 → 출입국 기록 팝업
6. 입국일자가 있는 기록을 선택하고 `수정(Update)` 클릭
7. 유학생기본정보 상세화면으로 돌아가 입국일자가 실제로 채워졌는지 확인
8. 확인되면 `입국신고 완료`, 안 되면 `별도 처리 필요`로 기록

[M-4. 안전 규칙 — 애매하면 멈춥니다]

아래 경우에는 아무 버튼도 누르지 않고 사유만 기록합니다.
담당자가 직접 확인해야 합니다.

- 성명·생년월일·학번이 모두 일치하는 행이 1건이 아닐 때
- 팝업의 출입국 기록 중 입국일자가 있는 것이 없을 때
- 입국일자가 있는 기록이 2건 이상일 때 (어느 것이 맞는지 자동으로 고르지 않음)
- 팝업의 성명·생년월일이 대상 학생과 다를 때

화면에 다른 학생이 함께 조회돼도 절대 선택하지 않습니다.
엑셀 명단의 학생만 처리합니다.

[M-5. 팝업 차단]

`수정 팝업 창을 찾지 못했습니다`가 나오면 브라우저 팝업 차단 때문입니다.
주소창 오른쪽 팝업 차단 아이콘에서 fims.hikorea.go.kr 팝업을 허용한 뒤
다시 실행하세요.

[N. 1.3.1에서 함께 고친 것]

1. 검색조건 입력에도 재시도를 넣었습니다.
   직전 학생 처리 후 검색화면으로 막 돌아온 순간에는 FIMS가 폼을 리셋해
   방금 넣은 값이 날아갈 수 있습니다. 실제로 마지막 학생에서
   "성명 실패 / 생년월일 실패 / 유사체크 OK"로 중단된 사례가 있었습니다.

2. 표에서 값을 읽을 때 빈 칸을 지나쳐 다음 항목의 라벨을 값으로
   읽던 문제를 고쳤습니다. (입학(복학)일자 값이 "출국일자"로 읽힌 사례)

3. 화면에 표시되는 버전을 manifest에서 직접 읽도록 바꿨습니다.
   예전에는 화면에 하드코딩돼 있어 버전을 올려도 v1.0.4로 남아 있었습니다.

[O. 1.3.1에서 고친 것 — 중요]

저장이 실제로 되지 않았는데 "저장은 완료됐으나 입국일자 미확인"으로
기록되던 문제를 고쳤습니다.

무엇이 문제였나:
  저장 버튼 클릭을 '예약'만 하고 곧바로 저장 완료로 간주했습니다.
  그 다음 검증이 아직 저장되지 않은 수정화면 자체를 읽어버렸고,
  학번은 방금 프로그램이 입력한 값이라 당연히 일치했습니다.
  결국 입국일자만 비어 있으니 '입국일자 미확인'으로 분류됐습니다.
  실제로는 학번도 입학일자도 하나도 저장되지 않은 상태였습니다.

이제는 아래 증거가 있어야만 저장으로 인정합니다.
  - FIMS의 저장 성공 알림, 또는
  - 읽기전용 입국일자가 채워짐 (서버를 거치지 않으면 불가능)

증거가 없으면 `입국정보 저장 실패`로 기록하고, 저장 버튼을 한 번 더 눌러
재시도합니다. FIMS가 경고창으로 거부하면 그 문구를 그대로 남깁니다.
예전에는 이 경고창을 프로그램이 조용히 닫아버려 원인을 알 수 없었습니다.

중요: `입국정보 저장 실패`는 별도처리 대상이 아닙니다.
저장 자체가 안 된 것이므로 입국신고를 다시 해야 합니다.

[P. 1.3.1에서 고친 것]

1. 최종출신학교 특수문자 때문에 저장이 거부되던 문제

   FIMS는 저장할 때 화면 전체를 검사합니다. 최종출신학교에
   쉼표 같은 문자가 들어 있으면 우리가 그 칸을 건드리지 않아도
   저장이 거부됩니다.

     FIMS 알림: 최종출신학교에 -,(,),. 이외의 특수문자를
                입력하실 수 없습니다.

   이제 저장 전에 허용되지 않는 문자만 공백으로 바꾸고
   연속 공백을 정리합니다. 학교명 자체는 그대로 둡니다.

     University of Applied Sciences, Worms
     -> University of Applied Sciences Worms

   허용 문자: 한글·영문·한자 등 글자, 숫자, 공백, 그리고 - ( ) .
   문제가 없는 학교명은 손대지 않습니다.
   정리한 경우 처리결과 상세메시지에 변경 전후가 기록됩니다.

2. 수정대상자 목록에서 학생을 찾지 못하던 문제

   이 화면은 성명·생년월일·외국인등록번호를 노란 입력칸으로 보여줍니다.
   프로그램이 화면 글자만 읽고 입력칸 값은 읽지 않아, 학생이 눈에
   보이는데도 "수정대상자 목록에서 해당 학생을 찾지 못했습니다"가 떴습니다.
   이제 입력칸 값까지 함께 읽습니다.

   대상 학생만 고르는 규칙(성명·생년월일·학번 모두 일치, 정확히 1건)은
   그대로입니다. 화면에 함께 뜬 다른 학생은 여전히 건드리지 않습니다.

[Q. 1.3.1에서 고친 것 — 별도처리가 학생을 못 찾던 문제]

1. 여권번호 때문에 대상 학생이 탈락하던 문제

   수정대상자 목록에는 학번 열이 없습니다.
   (순번 / 성명·성별 / 등록번호·여권번호 / 생년월일·국적 /
    체류자격 / 입국·입학일자 / 교육과정 / 수정)

   그런데 프로그램이 행의 숫자를 학번과 대조하면서, 여권번호
   EQ7555520 의 숫자 부분 7555520 을 학번 후보로 잘못 잡아
   학생이 화면에 보이는데도 계속 탈락시켰습니다.

   이제 행에서는 성명·생년월일만 확인합니다.
   학번은 검색조건으로 FIMS가 이미 걸러줍니다.

2. 팝업의 입국일자를 못 읽던 문제

   수정 팝업의 입국일자는 20260824 처럼 점이 없는 8자리입니다.
   프로그램은 2026.08.24 형태만 찾고 있어서
   "입국일자가 있는 기록이 없습니다"로 멈췄습니다.
   이제 두 형식 모두 읽습니다.
   (날짜가 아닌 8자리 숫자는 날짜로 보지 않습니다.)

3. 수정대상자로 분류되지 않은 학생

   조회 화면의 `재학생정보수정대상자` 체크를 켜두면 수정대상자로
   분류된 학생만 나옵니다. 그래서 못 찾는 경우가 있었습니다.
   이제 못 찾으면 체크를 풀고(전체 재학생) 한 번 더 조회합니다.

   조회 조건은 성명·생년월일·학번 세 항목뿐입니다.
   등록번호·교육과정은 입력하지 않습니다.
   성명·생년월일이 일치하는 행이 정확히 1건일 때만 진행하는
   규칙은 그대로입니다.

4. 수정 팝업 결과도 증거로 판정합니다

   수정(Update) 후 확인창은 자동 승인하고, FIMS의 성공 알림을
   확인해야 반영된 것으로 봅니다. 성공이 아닌 알림이 뜨면
   그 문구를 그대로 기록합니다.

[R. 1.3.1에서 고친 것 — 버튼을 눌러도 아무 일이 없던 문제]

개발자도구 콘솔에 아래 오류가 보이는 경우가 있었습니다.

  Running the JavaScript URL violates the following Content Security
  Policy directive ... The action has been blocked.
  (content.js clickTarget)

FIMS 링크 중 일부는 <a href="javascript:함수()"> 형태입니다.
확장프로그램에서 이 링크를 클릭하면 브라우저 보안정책이 그 실행을
차단합니다. 클릭은 됐는데 아무 일도 일어나지 않는 상태가 됩니다.

이제 이런 링크는 클릭하는 대신 페이지의 함수를 직접 호출합니다.
평범한 함수 호출이라 보안정책에 걸리지 않습니다.

해석할 수 없는 형태(this, 계산식 등)나 javascript:void(0) 같은 것은
예전처럼 그냥 클릭합니다.

이 오류가 보였다면 그동안 일부 버튼이 눌리지 않았을 수 있습니다.
저장이나 별도처리가 조용히 실패한 경우 이것이 원인일 수 있습니다.

[S. 현지추천단체·현지추천단체구분·최종출신학교 (1.3.1 신규)]

입국신고명단 탭에 세 개 열이 추가됐습니다.

  F열: 현지추천단체
  G열: 현지추천단체구분
  H열: 최종출신학교

규칙은 하나뿐입니다.

  비워두면  → FIMS에 입력된 값을 그대로 둡니다. 건드리지 않습니다.
  값을 적으면 → 그 값으로 덮어씁니다.

교환방문 학생은 비워두시면 됩니다.
학위과정 학생처럼 "-" 를 넣어야 하는 경우에만 해당 칸에 - 를 적으세요.

현지추천단체구분은 콤보라서 아래 중 하나여야 합니다.
표시문자로 적어도 되고 코드로 적어도 됩니다.

  코드  표시문자
  20    대학자체현지모집
  30    현지유학원추천
  40    개인직접신청
  50    현지자매학교추천
  90    기타

선택지에 없는 값을 적으면 그 학생의 구분은 바꾸지 않고
처리결과 상세메시지에 "추가입력 실패"로 남깁니다.

무엇을 입력했는지는 처리결과 상세메시지에 "추가입력: ..." 으로 기록됩니다.

[T. 입학(복학)일자 형식 문제 수정]

엑셀에는 20260901 로 적지만 FIMS 화면에는 2026.09.01 로 들어가야
저장이 됩니다. 20260901 그대로 남아 있으면 저장되지 않습니다.

프로그램의 검증이 점을 떼고 숫자만 비교하고 있어서, 화면에 20260901 로
남아 있어도 정상으로 판단하고 그냥 저장을 시도했습니다.
이제 점이 있는 형식과 정확히 일치하는지 확인하고, 어긋나면 다시 넣습니다.
그래도 안 되면 아래처럼 기록합니다.

  입학(복학)일자가 "20260901" 형식으로 남아 있습니다.
  FIMS는 "2026.09.01" 형식이어야 저장됩니다.

엑셀에는 그대로 20260901 로 적으시면 됩니다. 변환은 프로그램이 합니다.

[U. 1.3.1 — 입국일자 미확인이 갑자기 늘어난 이유]

저장이 잘 됐는데도 "입국일자 미확인"으로 기록되는 일이 최근 부쩍 늘었습니다.
원인은 화면을 너무 빨리 읽는 것이었습니다.

FIMS가 저장할 때 순서는 이렇습니다.

  1. 저장 요청을 보낸다
  2. "성공적으로 저장되었습니다" 알림이 뜬다
  3. 그 다음에 화면이 다시 그려지면서 입국일자가 채워진다

그런데 프로그램은 2번 알림을 보자마자 판정을 끝냈습니다.
그 시점의 화면은 아직 3번 전이라 입국일자가 비어 있습니다.
그래서 저장은 됐는데 "입국일자 미확인"으로 남았습니다.

이제 알림을 봐도 바로 끝내지 않고, 입국일자가 채워질 때까지
최대 15초 더 기다린 뒤에 판정합니다.

함께 손본 것:

  - 상세화면·수정화면은 같은 화면이 연속 두 번 확인돼야 진행합니다.
    화면이 바뀌는 중에 예전 화면을 읽는 일이 없어집니다.
  - 수정화면에 들어간 뒤 1.2초 기다렸다가 입력합니다.
    FIMS 자체 스크립트가 값을 채우는 중에 입력하면 덮어써질 수 있습니다.
  - 상세화면 진입 후 0.8초 기다립니다.

학생 한 명당 2~4초 정도 더 걸립니다.
실행 로그에 학생별 소요 시간이 (00.0초)로 표시됩니다.

주의: 이 수정 이후에도 "입국일자 미확인"이 남는 학생은
관서 출입국 기록이 실제로 연결되지 않은 경우입니다.
그 학생은 별도처리 섹션에서 처리하시면 됩니다.
