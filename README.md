# FIMS 자동화 (한양대 국제처 업무용)

법무부 유학생정보시스템(FIMS) 입국신고·졸업신고를 Excel 명단으로 자동 처리하는
Chrome 확장프로그램입니다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `fims_arrival_rpa/` | **입국신고** 확장프로그램 소스 (현재 1.3.0) |
| `fims_graduation_rpa/` | 졸업신고 확장프로그램 소스 (v3.0.1, 이번 작업 범위 밖) |
| `dist/` | 설치용 ZIP |
| `docs/` | 개발 인계서 |
| `reference/` | FIMS 화면 요소 수집본 (셀렉터 근거) |

## 바로 설치하기

1. `dist/FIMS_입국신고_자동화_v1.3.0.zip` 다운로드
2. 압축 풀기 — 폴더를 열면 `manifest.json`이 **바로 보입니다**
3. Chrome 주소창에 `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** → 2번 폴더 선택
5. 버전이 `1.3.0`인지 확인

자세한 사용법은 `fims_arrival_rpa/설치안내.txt` 참고.

## v1.0.5에서 고친 것

1.0.4는 소스만 있고 설치용 ZIP이 없어서, 실제로는 결함이 있는 1.0.3이 계속 사용되고
있었습니다. 1.0.5는 아래를 고치고 설치 가능한 형태로 패키징한 버전입니다.

| 결함 | 증상 | 근거 |
|---|---|---|
| 수정화면 URL `IntlStudBaInfoDtlRU.xec`를 URL 판정 정규식이 놓침 | 저장 후 화면 판정 실패 | `reference/` 수집본에서 해당 URL 확인 |
| 저장 후 읽기전용 상세화면만 기다림 | **저장 성공을 45초 뒤 실패로 기록** | 저장 후 수정화면에 남는 경우가 있음 |
| 안내창 로그를 첫 프레임에서만 초기화 | **간헐적 "FIMS 로그인 실패"** (localStorage는 쿠키 삭제로 안 지워짐) | 오리진별 localStorage 분리 |
| 로그인 버튼 클릭 실패 플래그를 아무도 읽지 않음 | 60초 대기 후 엉뚱한 메시지 | 설정만 하고 참조 0회 |
| 테스트가 `CODEX_PRIMARY_RUNTIME_NODE_MODULES` 의존 | 해당 개발환경 밖에선 실행 불가 | 실제로 실행 시 즉시 예외 |

각 결함은 회귀 테스트로 잠가뒀습니다. 수정 전 코드에 돌리면 실패하는 것을 확인했습니다.

## 조회만 진단하기

실제 저장 없이 어디서 막히는지만 확인하는 모드입니다.
검색·상세조회까지만 하고 **수정·저장은 호출하지 않습니다**(테스트로 잠가둠).

실행 화면 → `진단 (조회만 · 저장 안 함)` → 끝나면 `진단 리포트 저장`.

리포트에는 각 단계의 성공/실패, 프레임 구조, 요소 존재·잠금·길이가 담기고,
**성명·생년월일·학번은 글자 수와 쉼표 위치만 남긴 형태로 가려집니다**
(예: `SURNAME, GIVEN` → `XXXXXXX, XXXXX`). FIMS 계정 정보는 수집하지 않습니다.

## 입국일자 미확인 별도처리 (v1.3.0)

입국신고는 저장됐지만 입국일자가 뜨지 않는 학생은 관서(출입국) 기록과 아직
연결되지 않은 경우입니다. 실행 화면의 **입국일자 미확인 별도처리** 섹션에서
`재학생정보 수정대상자 조회 및 수정`(`#nMenuTreeHome8`) 화면을 통해 처리합니다.

처리결과 엑셀을 다시 올리면 지난 실행 결과를 이어받아 대상자만 골라냅니다.

**정확성 우선 — 애매하면 아무것도 누르지 않습니다.** 아래는 모두 `별도 처리 필요`로
기록만 남깁니다.

- 성명·생년월일·학번이 모두 일치하는 행이 1건이 아닐 때
- 팝업의 출입국 기록에 입국일자가 없을 때
- 입국일자가 있는 기록이 2건 이상일 때
- 팝업의 신원이 대상 학생과 다를 때

화면에 함께 조회된 다른 학생은 절대 선택하지 않습니다 (`tests/test-modiobj.mjs`가 잠금).

조회 조건은 **성명·생년월일·학번** 세 항목뿐이다. 이 목록에는 학번 열이 없으므로
행에서는 성명·생년월일만 대조한다 — 예전에는 여권번호(`EQ7555520`)의 숫자 부분을
학번 후보로 잡아 조회된 학생을 계속 탈락시켰다. `재학생정보수정대상자` 체크를 켜면
수정대상자로 분류된 학생만 나오므로, 못 찾으면 체크를 풀고(전체 재학생) 한 번 더 조회한다.

팝업의 입국일자는 `20260824`처럼 구분자가 없다. 두 형식 모두 읽되, 월·일 범위를
검사해 아무 8자리 숫자나 날짜로 보지 않는다.

## 저장 판정은 증거 기반 (v1.3.0)

저장 버튼을 눌렀다고 저장된 것이 아니다. 아래 증거가 있어야만 `입국신고 완료`로
기록한다.

- FIMS의 저장 성공 알림, 또는
- 읽기전용 입국일자(`#eYmd`)가 채워짐 — 서버 왕복 없이는 불가능

증거가 없으면 `입국정보 저장 실패`(별도처리 대상 아님)로 남기고 저장을 한 번
재시도한다. FIMS가 경고창으로 거부하면 그 문구를 그대로 기록한다 — 예전에는
대화상자 브리지가 이 경고를 조용히 삼켜 원인을 알 수 없었다.

`입국일자 미확인`은 이제 **저장이 확인된** 학생에게만 붙는다. 별도처리 대상이
정확해진다.

## 최종출신학교 자동 정리 (v1.3.0)

FIMS는 저장 시 화면 전체를 검증한다. 최종출신학교(`#lastOriSchol`)에 허용되지
않는 특수문자가 있으면 우리가 그 칸을 건드리지 않아도 저장이 거부된다.

> FIMS 알림: 최종출신학교에 -,(,),. 이외의 특수문자를 입력하실 수 없습니다.

저장 전에 허용되지 않는 문자만 공백으로 치환하고 연속 공백을 정리한다.
허용: 글자(`\p{L}`)·숫자(`\p{N}`)·공백·`-`·`(`·`)`·`.`

```
University of Applied Sciences, Worms  ->  University of Applied Sciences Worms
ABC,DEF                                ->  ABC DEF
Seoul Nat.-Univ. (Main)                ->  (변경 없음)
```

문제가 없으면 손대지 않으며, 정리한 경우 처리결과 상세메시지에 변경 전후를 남긴다.

## javascript: 링크 클릭 (v1.3.0)

FIMS 링크 중 일부는 `<a href="javascript:fnc()">` 형태다. 확장에서 `element.click()`
으로 누르면 브라우저가 그 javascript: URL 실행을 CSP 위반으로 차단한다
(`The action has been blocked`) — 클릭은 되지만 아무 일도 일어나지 않는다.

이런 링크는 함수명과 단순 리터럴 인자만 뽑아 MAIN world(`dialog-bridge.js`)에서
`window[fn](...args)` 로 직접 호출한다. eval도 inline script도 아니라 CSP에 걸리지 않는다.
해석할 수 없는 형태(`this`, 표현식, `void(0)`)는 기존대로 클릭한다.

## 엑셀 선택 입력 (v1.3.0)

`입국신고명단` 탭에 **현지추천단체 / 현지추천단체구분 / 최종출신학교** 열을 추가했다.
규칙은 하나 — **비워두면 FIMS 값을 건드리지 않고, 값을 적으면 덮어쓴다.**
학위과정 학생처럼 `-` 가 필요한 경우에만 해당 칸에 적으면 된다.

| 엑셀 열 | FIMS 필드 |
|---|---|
| 현지추천단체 | `#lcRecomEntity` |
| 현지추천단체구분 | `#lcRecomEntityGb` (select: 20/30/40/50/90 — 표시문자·코드 둘 다 허용) |
| 최종출신학교 | `#lastOriSchol` |

## 입학(복학)일자 형식

FIMS는 `2026.09.01` 형식이어야 저장한다. `20260901` 로 남아 있으면 저장되지 않는다.
예전 검증은 `digits()` 로 점을 떼고 비교해 두 형식을 모두 통과시켰기 때문에 이 문제를
잡지 못했다. 이제 점 포함 형식과 정확히 일치해야 하고, 어긋나면 다시 넣은 뒤 그래도
안 되면 실패로 기록한다.

## ⚠️ 실사이트 검증 상태

**1.0.5는 로컬 자동 테스트만 통과했고, 실제 FIMS에서는 아직 검증되지 않았습니다.**
반드시 학생 1명으로 먼저 시험한 뒤 전체 명단에 사용하세요.
로컬 테스트는 DOM·Chrome API 모의(mock) 기반이라 실제 프레임 갱신, 브라우저 자동완성,
네이티브 대화상자, 팝업 차단까지는 보장하지 않습니다.
